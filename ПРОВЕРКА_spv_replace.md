# Как проверить, что spv_replace работает — на твоей R7 260X

Вторая видеокарта не нужна. Проверка делается **на твоём же компьютере**, потому что
`spv_check.exe` берёт твои файлы из `spv_replace`, «пересобирает» их так, как это сделал бы
драйвер **другой** карты (новые номера регистров, другой порядок команд, без отладочных
имён, другой размер), и смотрит, узнаёт ли их код прокси. Если узнаёт — значит на NVIDIA и
Intel этот же файл тоже будет принят.

---

## Часть 1. Проверка папки (2 минуты, игру запускать не надо)

1. Открой папку, где лежит `vulkan-1.dll` (например `F:\Visual Studio\VulkanProxy\INDIANA_AGENT`).
2. Убедись, что рядом лежат три вещи: `vulkan-1.dll`, `VulkanProxy.ini`, папка `spv_replace`.
3. Скопируй в эту папку два файла из архива: `build_spv_check.bat` и `spv_check.cpp`.
4. Двойной щелчок по **`build_spv_check.bat`**.
   Он сам найдёт Visual Studio, соберёт `spv_check.exe` и сразу его запустит.
5. Читай вывод. В самом низу будет одна из двух строк:

   - `PASS: 3/3 replacement(s) are recognised...` — **всё хорошо**, папка переносимая.
   - `FAILED` / `[bad ]` — плохо, пришли мне текст этого окна.

Что означают строчки в середине:

| Строчка | Значение |
|---|---|
| `spv_XXXXXXXX...  compute  10414 words, 41 descriptors, 0 names` | файл прочитан; `0 names` — нормально, у тебя тоже без отладочных имён |
| `[bad ] ... not readable as SPIR-V` | файл битый/не SPIR-V, кинь мне его имя |
| `stripped+shuffled: FOUND (identical)` | после «пересборки как на другой карте» файл найден ✓ |
| `named+shuffled: FOUND (identical)` | то же с именами ✓ |

Если папка другая — запусти из консоли с путём:
`spv_check.exe "F:\путь\к\spv_replace"`

---

## Часть 2. Проверка в самой игре (одна карта, твоя R7 260X)

Раньше смысл был такой: на твоей карте замены применялись, а на чужой — нет. Теперь нужен
только один запуск, чтобы убедиться: **новый код не сломал твой рабочий путь**.

1. Собери заново `vulkan-1.dll`: правой кнопкой по `build_proxy.ps1` →
   **«Выполнить с помощью PowerShell»**. Ждём `Built: ...vulkan-1.dll`.
   (Если PowerShell ругается на политику запуска:
   `powershell -ExecutionPolicy Bypass -File .\build_proxy.ps1`.)

   Перед `cl.exe` скрипт сам запускает маленькую проверку
   `tools\check_namespace_scope.py` и печатает
   `OK: every spvrw symbol used outside the namespace is qualified or forwarded`.
   Если вместо этого `FAIL` — пришли эти строки, там будет точный номер
   строки в `dllmain.cpp` и имя символа (это дешевле, чем полная сборка).
2. Проверь в `VulkanProxy.ini` эти строки — должно быть ровно так:

   ```
   UseReplacements=1
   FuzzyMatch=1
   StructureMatchFallback=1
   FollowHardwareCaps=1
   SelfTest=1
   ```

   `SelfTest=1` включает самопроверку **внутри игры** — она делает то же самое, что
   `spv_check.exe`, но на реальных модулях твоей карты.
3. Запусти игру, дойди до меню (дальше можно не идти), выйди.
4. Открой `VulkanProxy_diagnostic.log` (блокнотом) и поищи по Ctrl+F:

   **`SELFTEST`** → должна быть строка
   `SELFTEST PASSED: 3/3 replacement(s) were still found ... The folder is portable.`

   **`replacement index`** → там `3 file(s)` и `similarity candidates=3`
   (`0 file(s)` = папка не видна, `unreadable` > 0 = файлы побились).

   **`no replacement for hash=`** → если такие строки есть, рядом теперь написана причина,
   например:
   `closest spv_801f80bf7bdfa946.spv: shape=0.62 layout=0.40 (need shape>=0.75, layout>=0.50...)`.
   Это и есть то, что я просил раньше «пришли лог» — теперь причина видна сразу.
   А если там `stage 5 (compute) not present` — значит для этой стадии файла в папке нет.

   **`shader replacement matched (...)`** → замена принята по сходству (а не по точному
   хешу). Именно это и должно происходить на чужой карте.

5. Альтернатива пункту 4 — запустить `.\check_spv_replace.ps1` в той же папке: он сам
   вытащит всё перечисленное и подсветит.

### Как понять результат

- `SELFTEST PASSED` + `replacement index: 3 file(s)` → **готово**, папка универсальная.
- `SELFTEST FAILED` → пришли лог, буду смотреть конкретный файл.
- `SELFTEST: spv_replace is empty` → `spv_replace` не рядом с DLL (пункт 2 части 1).

## Часть 3. Частые вопросы

**Надо ли ещё что-то менять в INI под каждую карту?** Нет. Все ключи из части 2 — это
значения по умолчанию; ничего под NVIDIA/Intel подкручивать не нужно.

**Игра всё ещё чёрная?** Смотри `=> FAKE module (reason=...)` в логе: это шейдер, который
прокси заменил заглушкой ради обхода проверок, — он и даёт чёрный экран. Пришли мне такую
строку целиком, там теперь указан номер шейдера и причина.

**Почему нельзя просто доверять точному хешу?** Хеш считается от байтов, а байты у каждой
карты свои (номера регистров, порядок команд, наличие отладочных имён). Сравнение теперь
идёт по набору команд и интерфейсу — они от карты не зависят.
